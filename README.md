## 二、数据怎么流（一张图看懂）

```
P 老板 / Garnett 下令
        │
GitHub Actions（定时器+调度）──ping 保活──► Supabase（任务队列/状态库）
        │                                      ▲  ▲
        ├─ 触发批处理 ─► Kaggle / Colab（GPU 活，干完把结果写回）
        ├─ 调用轻服务 ─► Cloady（常驻 worker，领任务/报结果）
        └─ 每日汇总 ───► 报告落 R2
Cloudflare Workers（对外入口/Webhook）─► 写任务进 Supabase
OpenRouter（轻 LLM）◄─ Cloady / Actions 按需调用（≤50 次/天预算）
R2（文件仓）◄─ 各牛马交付物归档；Sakupa（橱窗）─ 展示状态页/落地页
```

原则：**状态只存一处（Supabase），文件只存一处（R2），定时只靠一处（Actions），对外入口只开一处（Workers）。** 牛马死了换一台，数据不丢。
